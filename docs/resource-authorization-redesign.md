# 资源授权页面全面改版方案

## 1. 背景与目标

当前页面以人员分类页签作为主要入口。数据量增大后，管理员必须先知道人员属于哪个分类，才能找到并操作，导致查找路径长、重复切换分类，并容易遗漏多重身份人员。

本次改版目标：

1. 不需要预先知道人员分类，也能快速找到目标人员。
2. 清楚展示人员的全部身份、组织归属及当前授权状态。
3. 同时支持单人、批量授权和取消授权。
4. 在大数据量下保持稳定的查询和操作体验。
5. 对取消授权、跨页全选等高风险操作提供必要保护。

核心验收场景：管理员完全不知道某人属于哪个分类，仅输入昵称或账号，即可找到该人员、查看全部身份和授权状态，并直接完成授权或取消授权。

## 2. 整体信息架构

将现有“按分类逐个查找”的弹窗改造成“全局检索 + 多维筛选 + 授权管理”的统一工作区。

数据量长期较大时，推荐采用全屏抽屉或独立页面；若继续使用弹窗，应扩大宽高，并只让表格区域滚动。

## 3. 一级视图与分类方式

将授权状态设为一级视图：

- 全部人员
- 已授权
- 未授权

每个视图显示动态数量，例如：

- `全部人员 1268`
- `已授权 86`
- `未授权 1182`

原有的长执、教师、会友、新人、事工同工、组长、统筹同工、班级、小组等分类保留，但改为多选筛选条件。这样既能快速查看当前资源已授权给谁，也能按业务身份缩小范围。

## 4. 全局搜索

搜索默认覆盖全部人员和全部分类，支持：

- 昵称
- 账号

搜索框提示文字为：`搜索昵称或账号`。

交互规则：

1. 输入后延迟约 300 ms 自动搜索，按 Enter 可立即搜索。
2. 支持模糊匹配并高亮命中文字。
3. 提供一键清空入口。
4. 结果中直接显示所属分类，不要求用户先选择分类。
5. 同一人员属于多个分类时只显示一行，避免重复授权。
6. 没有结果时提供“清除筛选”和“搜索全部人员”入口。

多重身份采用标签展示：

```text
张三    zhangsan    [教师] [组长] [一班]
```

标签过多时显示前两个，其余折叠为 `+N`，悬浮或点击后查看完整信息。

## 5. 筛选设计

| 筛选项 | 选项 | 选择方式 |
| --- | --- | --- |
| 人员分类 | 长执、教师、会友等 | 多选 |
| 授权状态 | 全部、已授权、未授权 | 单选 |
| 班级 | 具体班级 | 多选、可搜索 |
| 小组 | 具体小组 | 多选、可搜索 |
| 账号状态 | 正常、停用 | 单选或多选 |

班级和小组筛选可根据人员分类动态出现，避免默认界面过于复杂。

已选条件以标签显示，并提供统一重置：

```text
教师 ×   组长 ×   未授权 ×                     [重置]
```

## 6. 列表字段

| 字段 | 说明 |
| --- | --- |
| 勾选框 | 用于批量操作 |
| 姓名/昵称 | 主信息，可同时展示头像 |
| 账号 | 辅助识别人员 |
| 所属分类 | 展示全部身份标签 |
| 所属组织 | 班级、小组等具体归属 |
| 授权状态 | 已授权或未授权 |
| 授权时间 | 已授权时显示 |
| 授权人 | 记录操作人员 |
| 操作 | 根据状态显示授权或取消授权 |

授权时间、授权人可以在空间不足时放入详情浮层。状态视觉建议：

- 已授权：绿色圆点或绿色标签。
- 未授权：灰色标签。
- 处理中：蓝色加载状态。
- 操作失败：红色状态并提供重试。

操作列只展示当前有效操作：

```text
未授权 → 授权
已授权 → 取消授权
```

## 7. 单人授权

未授权人员的操作列显示“授权”。

流程：

1. 点击后按钮进入加载状态，防止重复提交。
2. 成功后状态立即变为“已授权”。
3. 操作按钮切换为“取消授权”。
4. 提示“已授权给张三”。
5. 同步更新顶部已授权和未授权数量。

普通单人授权不要求二次确认。若授权会触发通知、费用等副作用，应增加确认说明。

## 8. 单人取消授权

已授权人员的操作列显示“取消授权”。取消授权必须二次确认：

```text
取消张三的资源访问权限？

取消后，张三将无法继续查看或使用当前文件夹及其中的资源。

[暂不取消]  [确认取消授权]
```

如果权限会继承到子资源，确认框需明确说明影响范围。

确认成功后：

1. 状态变为“未授权”。
2. 操作切换为“授权”。
3. 提示“已取消张三的授权”。
4. 同步更新数量。

## 9. 批量授权与取消授权

勾选人员后，在表格上方显示固定批量操作栏：

```text
已选择 12 人，其中已授权 4 人、未授权 8 人
[授权未授权的 8 人] [取消已授权的 4 人] [清空选择]
```

### 9.1 批量授权

确认框显示实际生效人数及分类分布：

```text
确认授权给以下 8 人？

教师 3 人
会友 2 人
班级成员 3 人

已授权人员将自动跳过。

[取消] [确认授权]
```

### 9.2 批量取消授权

批量取消属于高风险操作，必须二次确认：

```text
确认取消 6 人的资源访问权限？

取消后，这些人员将无法继续访问当前资源。
该操作可通过重新授权恢复。

[返回] [确认取消授权]
```

建议根据人数提高确认强度：

- 取消 1～5 人：普通二次确认。
- 取消 6 人及以上：要求输入资源名称。
- 取消全部授权：必须输入资源名称并再次明确影响人数。

### 9.3 部分成功

批量请求必须支持部分成功，完成后显示：

```text
授权完成：成功 7 人，失败 1 人
[查看失败人员] [重试失败项]
```

失败人员保留勾选状态，成功人员取消勾选，方便直接重试。

## 10. 全选与跨页选择

第一次点击表头复选框时，仅选择当前页：

```text
已选择当前页 50 人
当前筛选条件下共有 382 人，是否选择全部 382 人？
[选择全部 382 人]
```

选择全部筛选结果后明确显示：

```text
已选择当前筛选结果中的全部 382 人                    [取消全选]
```

用户修改搜索或筛选条件时，应清空选择并提示，避免对不可见人员误操作。

## 11. 操作后的列表行为

- “全部人员”视图：人员保留在原位置，仅更新授权状态。
- “未授权”视图完成授权：该人员淡出并从列表移除。
- “已授权”视图取消授权：该人员淡出并从列表移除。
- 批量操作完成后保留搜索、筛选、页码和滚动位置。
- 不因操作完成自动跳回第一页。

单人操作后可短暂提供反向操作入口：

```text
已取消张三的授权                              [重新授权]
```

该入口应执行真实的反向接口，而不是只恢复前端状态。

## 12. 页面状态

### 12.1 没有已授权人员

```text
当前资源还没有授权给任何人员
你可以从“未授权”列表中选择人员进行授权。

[查看未授权人员]
```

### 12.2 搜索无结果

```text
没有找到“zhangsan”
请检查账号，或清除人员分类和组织筛选。

[清除筛选]
```

### 12.3 当前分类无结果

```text
“教师”分类中没有找到该人员
是否在全部人员中搜索？

[搜索全部人员]
```

### 12.4 加载失败

```text
人员列表加载失败
请检查网络后重试。

[重新加载]
```

列表首次加载使用骨架屏；翻页、筛选和搜索时保留现有内容并显示局部加载状态，减少页面闪烁。

## 13. 性能与接口建议

人员数据采用服务端搜索、筛选、排序和分页，不一次加载全部人员。默认每页 50 条，可切换 20、50、100 条。

### 13.1 查询参数

```ts
interface AuthorizationListParams {
  resourceId: string
  keyword?: string
  authorizationStatus?: "authorized" | "unauthorized"
  categoryIds?: string[]
  classIds?: string[]
  groupIds?: string[]
  accountStatus?: "active" | "disabled"
  page: number
  pageSize: number
  sortBy?: "nickname" | "account" | "authorizedAt"
  sortOrder?: "asc" | "desc"
}
```

### 13.2 人员数据结构

```ts
interface AuthorizationUser {
  userId: string
  nickname: string
  account: string
  phone?: string
  avatar?: string
  categories: Array<{
    id: string
    name: string
  }>
  organizations: Array<{
    id: string
    name: string
    type: "class" | "group"
  }>
  authorized: boolean
  authorizedAt?: string
  authorizedBy?: string
}
```

### 13.3 接口建议

```text
GET    /resources/{resourceId}/authorization-users
POST   /resources/{resourceId}/authorizations
DELETE /resources/{resourceId}/authorizations
```

批量请求体：

```json
{
  "userIds": ["u1", "u2", "u3"]
}
```

部分成功响应：

```json
{
  "successUserIds": ["u1", "u2"],
  "failedItems": [
    {
      "userId": "u3",
      "reason": "账号已停用"
    }
  ]
}
```

授权和取消授权接口应具备幂等性，避免重复点击、网络重试产生异常状态。

## 14. 权限、安全与审计

1. 仅具备资源授权权限的管理员可以进入页面和调用接口。
2. 前端按钮控制不能替代后端权限校验。
3. 不允许取消自身权限时，应禁用操作并说明原因。
4. 明确超级管理员和资源所有者是否允许被取消授权。
5. 停用账号默认不能新增授权。
6. 所有授权和取消授权操作都记录审计日志。

日志至少包含：

- 资源 ID 与资源名称
- 被操作人员
- 操作类型
- 操作人
- 操作时间
- 操作结果
- 失败原因

## 15. 响应式与视觉规范

桌面端使用完整表格；较窄窗口下：

- 隐藏授权人、授权时间等次要字段。
- 所属分类标签折叠。
- 操作列固定在右侧。
- 筛选条件收纳到“更多筛选”抽屉。
- 搜索框及批量操作栏保持可见。

操作视觉层级：

- 授权：品牌蓝色主操作。
- 取消授权：行内普通文字按钮，确认框中使用危险色。
- 批量取消授权：红色描边或危险按钮。
- 重置、清空选择：中性按钮。

## 16. 实施范围与优先级

### P0：本轮必须完成

1. 全部人员、已授权、未授权三个一级视图。
2. 跨分类全局搜索。
3. 人员分类、授权状态、班级和小组筛选。
4. 同一人员多重身份合并展示。
5. 单人授权和取消授权。
6. 批量授权和批量取消授权。
7. 当前页全选与跨页全选规则。
8. 二次确认与批量部分失败处理。
9. 服务端分页、搜索和筛选。
10. 加载、空数据、错误等完整状态。
11. 权限校验与操作日志。

### P1：建议同步完成

1. 保留筛选、页码和滚动位置。
2. 授权时间和授权人展示。
3. 批量失败项重试。
4. 响应式布局。
5. 最近使用筛选条件。

### P2：后续增强

1. 保存常用筛选方案。
2. 导出已授权人员清单。
3. 授权变更历史查看。
4. 按人员、班级或小组进行整组授权。

## 17. 验收清单

- [ ] 不选择人员分类也能搜索到任意人员。
- [ ] 搜索结果展示人员全部分类和组织归属。
- [ ] 多重身份人员不会重复出现。
- [ ] 可以完成单人授权和单人取消授权。
- [ ] 可以对混合授权状态的人员执行准确的批量操作。
- [ ] 批量操作部分失败时可查看原因并重试。
- [ ] 当前页全选和全部筛选结果全选有明确区别。
- [ ] 取消授权前能够清楚看到影响范围和人数。
- [ ] 操作后数量、行状态和当前视图同步更新。
- [ ] 搜索、筛选、翻页和操作均有加载及错误反馈。
- [ ] 大数据量下列表通过服务端分页稳定运行。
- [ ] 无权限用户无法通过前端或直接调用接口执行操作。
- [ ] 授权和取消授权均产生完整审计日志。
- [ ] 常见桌面分辨率和窄屏窗口下均可正常使用。
